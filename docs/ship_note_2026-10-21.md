## What is done

- CSV-in, CSV-out validator on the offline `phonenumbers` library (Google libphonenumber port).
- Output columns: input, normalized, e164, valid_format, line_type, country, carrier, region_hint, extension, verdict (keep / drop / review), reason.
- Handles `+91` / `0` / `91` prefixes, spaces, dashes, dots, parentheses, `tel:` prefix, extensions, Excel scientific-notation and `.0` damage, country-column mismatch, de-duplication on E.164.
- 55 unit tests green, including a whole-file check that every row of the sample gets the expected verdict.

## Test data

No Data Team sample arrived today and there is no internal numbers file on my machine, so I generated a
200-row synthetic file (`data/samples/synthetic_200.csv`, fixed seed, no real numbers). It is deliberately
adversarial: Indian mobiles in 10 spellings, Indian landlines, US / UK / UAE numbers, toll-free, VoIP,
wrong-country rows, 25 broken cells, 10 Excel-mangled cells, 5 numbers each written 5 ways.

## How many rows layers 1 and 2 settle without a paid lookup

| | rows | share |
|---|---:|---:|
| keep (valid Indian/UK/UAE mobile, right country, first occurrence) | 108 | 54.0% |
| drop (invalid, landline, toll-free, Excel-destroyed, duplicate) | 65 | 32.5% |
| **settled offline** | **173** | **86.5%** |
| review (needs HLR: fixed-or-mobile ranges, VoIP, wrong country, mobile with extension) | 27 | 13.5% |

Count table: valid 182, invalid 16, mobile 139, landline 22, fixed-or-mobile 12, VoIP 4, toll-free 5,
wrong country 10, duplicates 20, Excel-mangled 9 (6 repaired, 3 unrecoverable).

On a real Indian-mobile-heavy file the offline share should be higher than 86.5%, because a quarter of
this sample is foreign, broken or duplicated on purpose.

## What offline cannot answer (why layer 3 is still needed)

- Whether the number is live or the SIM is active.
- Current carrier after number portability (offline carrier is the original allocation only).
- Mobile vs landline for US / Canada and a few Indian blocks (`fixed_or_mobile`).
- DND / NDNC status.
